# Methodology — Data Layer and Blocking

## Dataset

The study uses 188,042 company records from the ROC Pune subset of the MCA company master data. The records were cleaned and normalized before candidate generation.

## Blocking Strategy

To avoid comparing every company with every other company, blocking was used to generate a smaller set of candidate pairs.

The initial blocking experiment used two blocking keys:

1. Pincode blocking — companies sharing the same pincode are placed in the same block.
2. Name-prefix blocking — companies whose normalized company names share the same first four characters are placed in the same block.

The initial strategy produced oversized blocks for some common pincodes and company-name prefixes. These large blocks resulted in a very large number of candidate pairs.

To address this, a size-controlled blocking strategy was implemented with a maximum block size of 400 entities.

The updated strategy uses:

1. Pincode blocking — pincode groups containing 400 or fewer entities are expanded normally.
2. Pincode sub-blocking — oversized pincode groups are further divided using the first six characters of the normalized company name. Subgroups within the maximum block size are then expanded.
3. Six-character name-prefix blocking — the name-prefix length was increased from four to six characters. Groups containing more than 400 entities are not fully expanded.
4. Duplicate removal — candidate pairs generated by both blocking strategies are deduplicated using the entity ID pair.

Candidate pairs were generated with the constraint that `entity_id_a < entity_id_b`.

## Blocking Evaluation

For 188,042 entities, the number of possible naive all-pairs comparisons is:

17,679,802,861

The initial coarse blocking strategy produced:

267,584,864 candidate pairs

This represented a reduction of:

98.4865%

The updated size-controlled blocking strategy reduced the candidate set to:

4,270,091 candidate pairs

The resulting reduction ratio was:

99.9758%

Thus, the updated blocking strategy reduced the comparison space from approximately 17.68 billion possible pairs to approximately 4.27 million candidate pairs before the subsequent matching stage.

The reduction was achieved by limiting oversized blocks and applying secondary sub-blocking rather than expanding very large pincode or name-prefix groups into all possible pair combinations.

Recall impact of the updated blocking strategy should be evaluated separately during the matching and evaluation stage.
